Capítulo 1

Introducción al Ecosistema DeepSeek Harness

En el panorama actual de la IA generativa, la autonomía y la propiedad de los datos son los nuevos estándares de excelencia. DeepSeek Harness ha irrumpido con una fuerza sin precedentes, alcanzando las 100.000 estrellas en GitHub en solo dos días.

Se trata de un agente de código abierto diseñado para la acción continua. Sin embargo, utilizarlo en tu propia computadora es una limitación; la verdadera ventaja competitiva estratégica radica en poseer un servidor propio (VPS).

El agente solo trabaja cuando tú abres tu laptop. El flujo se detiene, la memoria se pierde y la ejecución depende de tu presencia física.

☁️ En un VPS propio

Memoria persistente y ejecución autónoma de largo plazo. Los agentes investigan, programan y despliegan soluciones 24/7 sin interrupciones.

Capítulo 2

Requisitos y Preparación del Servidor (VPS)

Como arquitecto de su propia infraestructura, su primera misión es elegir el terreno digital adecuado. No se trata solo de potencia, sino de eficiencia presupuestaria. Una mala elección puede resultar en cuellos de botella o gastos innecesarios.

Selección de plan: eficiencia vs. potencia

Para el ecosistema DeepSeek, se recomienda basarse en la siguiente comparativa de planes KVM (Kernel-based Virtual Machine):

PlanInversión estimadaPropósito estratégico
KVM2 ~$8/mes Suficiente para el Harness y orquestación vía API.
KVM4 Mayor capacidad Necesario para agentes pesados como Hermes u OpenClaw.

Proceso de despliegue paso a paso

  1. Instalación en un clic Utilice el instalador específico de DeepSeek Harness para evitar configuraciones manuales tediosas.
  2. Ubicación estratégica Seleccione servidores en East Coast Boston o West Coast Phoenix para minimizar la latencia.
  3. Optimización de costes Un experto siempre busca la eficiencia; asegúrese de aplicar el código moolucer para obtener un 10 % de descuento adicional.
⚠ IMPORTANTE · La llave maestra

Durante la configuración, deberá crear una Panel Password. Esta es la credencial de mayor nivel de su servidor. Anótala y guárdala en un gestor de contraseñas; sin ella, perderá el control administrativo del VPS.

Checklist de preparación

  • Plan elegido (KVM2 para Harness estándar).
  • Ubicación del servidor confirmada.
  • Contraseña del panel resguardada.
ℹ INFO

La elección del plan condiciona el tipo de agentes que podrá ejecutar. Si su objetivo es orquestar vía API, KVM2 es suficiente; si pretende ejecutar agentes pesados, necesitará KVM4.

Capítulo 3

Acceso y Configuración Inicial del Harness

Una vez que el «terreno» está listo, debemos entrar y configurar el motor de inteligencia. La estabilidad de su sistema depende de una configuración inicial limpia y estructurada.

Primer inicio de sesión

Acceda a través del dashboard de su proveedor. Las credenciales de entrada son:

CampoValor
Usuarioadmin
ContraseñaLa clave que definió en el paso anterior (Panel Password).

Arquitectura de trabajo

Para navegar con éxito, entienda estos dos conceptos:

💬 Sessions (Sesiones)

Son sus hilos de conversación o tareas activas.

📁 Workspaces (Espacios de trabajo)

Son las carpetas donde se organizan los archivos de un proyecto específico.

Conexión del motor (API)

Aunque puede usar llaves individuales, el uso de Open Router es la opción más inteligente. Le permite acceder a cientos de modelos (Claude, GPT, Gemini, DeepSeek) con una sola cuenta y un solo límite de gasto.

  1. Crear la API Key Cree su API Key en Open Router y establezca un límite de seguridad (ej. $20).
  2. Ir a la configuración En el Harness, diríjase a Settings > Function Models.
  3. Añadir proveedor Haga clic en Add Provider, seleccione Open Router y pegue su clave.
  4. Cargar el catálogo Use la función Fetch available models para cargar el catálogo actual.
✅ EJEMPLO

Con una única API Key de Open Router usted puede alternar entre Claude, GPT, Gemini y DeepSeek sin gestionar múltiples facturaciones ni múltiples claves.

⚠ ADVERTENCIA

Establezca siempre un límite de gasto en Open Router. Es una medida de seguridad económica que evita consumos inesperados por parte de agentes en ejecución continua.

Gestión de Modelos: De DeepSeek a Gemini 3.8 Flash

La flexibilidad es poder. En este entorno, usted no está atado a un solo modelo. Puede cambiar el «combustible» de su agente según la complejidad o el costo de la tarea.

⚡ DeepSeek V4 Flash

Excelente para tareas rápidas y económicas.

🚀 Gemini 3.8 Flash

El modelo de vanguardia preferido por su velocidad extrema de 5.000 tokens por segundo.

Instalación manual de modelos nuevos

Si un modelo acaba de ser lanzado y no figura en la lista:

  1. Copiar el Model ID Vaya a Open Router y copie el Model ID (ej. el de Gemini 3.8 Flash).
  2. Abrir la opción de modelo personalizado En Settings > Models, use la opción Custom Model Name.
  3. Registrar el modelo Pegue el ID y asigne un nombre de visualización.

Capítulo 5

Personalización Avanzada: Plugins y Temas

La personalización no es estética; es ergonomía cognitiva. Un entorno que responde visual y auditivamente mejora su productividad.

Acceso a la consola web (paso crítico)

Para instalar mejoras profundas, debe usar la terminal del VPS.

hostname

Obtenga su nombre de servidor con el comando anterior. Si el sistema indica que DSH no existe, instale npm:

sudo apt install npm

Instalación de plugins: feedback y gamificación

🔔 DSH bell notify

Emite un sonido al finalizar una tarea.

🐋 Whale on desk

Una mascota interactiva que sube de nivel y gana experiencia mientras usted trabaja, haciendo el proceso más alentador.

Comando de activación

Después de instalar un plugin, ejecute el comando de actualización en la consola y realice un Hard Reload en su navegador:

Ctrl + Shift + R
⚠ WARNING · Seguridad de temas

Al usar temas como «Liquid Glass», verifique siempre el repositorio de GitHub. No instale extensiones que no hayan sido vetadas por la comunidad, ya que podrían contener malware.

⛔ ERROR

Instalar un tema o extensión sin revisar su código fuente en GitHub expone su VPS —y todas las credenciales que contiene— a riesgos de seguridad.

hostname sudo apt install npm DSH bell notify Whale on desk Ctrl+Shift+R

Capítulo 6

Proyectos Prácticos: De Director a Creador

Aquí es donde ocurre la magia. Su rol cambia de «escribir código» a «dirigir a un agente que escribe código».

Técnica de prompting de alto nivel

Antes de iniciar cualquier proyecto complejo, obligue al agente a entender el contexto. Use siempre este bloque:

Prompt de contexto estratégicoHazme 10 preguntas críticas sobre lo que intento lograr con este proyecto. No empieces a trabajar hasta que yo responda y tú me hagas una pregunta de seguimiento para confirmar que entiendes perfectamente mi visión.

Caso práctico 1: El Cat Cafe de San Francisco

Utilice el Standard Mode para generar proyectos completos. Copie y pegue este prompt:

Prompt: Web Cat CafeConstruye un sitio web de ejemplo para un Cat Cafe en San Francisco. Hazlo divertido y juguetón, con micro-animaciones y juegos de palabras sobre gatos. Incluye arte SVG relacionado con café y gatos. Asegúrate de que todas las bebidas tengan nombres temáticos de gatos.

Solución al problema del localhost (acceso público)

En un VPS, el enlace localhost no funcionará en su navegador personal. Para visualizar su trabajo, debe usar la lógica de «Port Forwarding» o servir archivos públicamente. Use este comando/instrucción para su agente:

Prompt: Fix localhost / public URLConfigura el servidor para que los archivos generados sean accesibles a través de una URL pública. Utiliza mi hostname y un puerto específico para servir la web de modo que pueda verla desde mi navegador externo.
ℹ INFO

Este paso es imprescindible: sin él, el proyecto generado por el agente permanecerá inaccesible desde fuera del VPS.

Caso práctico 2: Paralelismo y comparación (Gemini vs Luna)

Una técnica experta es correr el mismo proyecto en dos modelos distintos. Puede usar Gemini 3.8 Flash en un workspace y OpenAI GPT 5.6 Luna en otro. Compare los resultados:

Destacará en velocidad.

🌙 OpenAI GPT 5.6 Luna

Ofrecerá un razonamiento de alto esfuerzo para diseños más complejos.

Caso práctico 3: Automatización «Morning Brief»

Aproveche que su servidor nunca duerme para programar tareas recurrentes:

Prompt: Morning Brief SchedulingGenera un resumen matutino (Morning Brief) que investigue las últimas noticias de mi sector y guarde un archivo .md con los puntos clave. Programa esta tarea para ejecutarse automáticamente todos los días a las 8:00 AM y almacena el resultado en el repositorio local 'Briefs'.
✅ EJEMPLO

Este caso demuestra el valor real de la ejecución autónoma de largo plazo: el agente trabaja a las 8:00 AM todos los días, aunque usted no esté conectado.

Capítulo 7

Finalización, Checklist y Glosario

Trayectoria de aprendizaje

Usted ha pasado de tener un servidor vacío a poseer una estación de trabajo de IA con:

  1. Infraestructura VPS KVM robusto.
  2. Motor Conexión API vía Open Router.
  3. Inteligencia Modelos de alta velocidad (Gemini) y razonamiento (Luna).
  4. Entorno Plugins de notificación y temas personalizados.

Checklist: errores comunes a evitar

  • Olvidar el Hard Reload: si instala un plugin y no lo ve, presione Ctrl+Shift+R.
  • Inseguridad en temas: siempre verifique el código en GitHub antes de instalar temas visuales.
  • Pérdida de credenciales: la Panel Password es irrecuperable en muchos casos; manténgala a salvo.

Glosario de términos

El túnel seguro para enviar comandos a su servidor.

Herramienta esencial para instalar extensiones y plugins.
Métrica de popularidad y confianza de un proyecto de código abierto.

De servidor vacío a estación de trabajo de IA: infraestructura, motor, inteligencia y entorno. El resultado es un sistema que trabaja por usted 24/7, sin depender de que su laptop esté encendida.
